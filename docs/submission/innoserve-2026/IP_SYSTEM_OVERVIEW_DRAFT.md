**中文專題名稱：** Policy Lab：實證支持型金融主張的可稽核決策與約束系統  
**英文專題名稱：** Policy Lab: Auditable Decisions for Evidence-Backed Financial Claims

## 一、前言

越來越多金融與數位資產應用依賴外部世界的資料，例如能源產量、環境憑證、資產估值、保險事件、抵押品狀態或其他可量測事實。然而，「有資料」並不等於「資料足以支持一項金融主張」。在實務系統中，資料如何被轉換成金融權限，往往分散在模型、規則、合約或機構流程中，使使用者難以回答四個基本問題：這份證據是否足夠？它最多能支持多少主張？是哪一條規則限制或阻擋了結果？即使主張成立，若後續無法完全履約會發生什麼事？

Policy Lab 的核心目標，是把這條隱藏的決策鏈轉換成可執行、可檢查、可重現的資訊系統。系統不把「資料存在」、「證據可信」、「可以提出金融主張」、「可以提出多少」、「能否完成結算」視為同一件事，而是分成獨立階段處理。每次決策都保留來源證據、保證層級、政策版本、通過或失敗的規則、數量上限、結算結果與決策識別碼，讓結果不只是畫面上的一個數字，而是可以被追查與挑戰的完整推理鏈。

目前公開版本以能源相關資料作為主要研究與展示領域，但架構本身面向更一般的「外部證據如何授權金融後果」問題。本作品不是虛擬貨幣發行計畫，也不主張目前的能源資料已足以證明貨幣或穩定幣成立；相反地，系統的重要功能之一，就是清楚標示證據尚不足以支持哪些主張。

## 二、創意描述

Policy Lab 的創新重點不在於再建立一個風險分數、資料儀表板或區塊鏈紀錄，而是將常被混在一起的五個問題拆開：

1. **資料存在不等於可信證據。** 系統保留資料來源、時間範圍、診斷與證據識別，不因資料公開、被雜湊或被寫入收據而自動提升可信程度。
2. **證據不等於金融授權。** 不同版本政策可以要求不同的來源保證與門檻，同一份證據可能在一個研究政策下通過，在更嚴格政策下被阻擋。
3. **通過不等於無限量。** 即使通過准入，系統仍計算多個可比較的數量上限，採用最嚴格的有效上限，並指出真正限制結果的規則。
4. **有效數量不等於一定能履約。** 結算與准入分開處理，讓「主張有效但結算不足」成為可觀察結果，而不是被成功發行所掩蓋。
5. **金融主張不等於貨幣。** 系統明確保留尚未驗證的制度、法律與市場邊界，不讓技術執行自動升級成更強的金融敘事。

目前最具代表性的公開案例 `PUB-AUSGRID-001P` 使用一份固定的外部 Ausgrid 公開資料。系統保留其實際保證層級為 L0，並對同一份證據套用兩個政策：較開放的研究政策產生 `ADMIT_WITH_LIMIT`，最高允許 33.066 kWh，且由「證據支持容量」成為限制上限；較嚴格的試點政策則因缺少簽章證據與最低來源保證而直接 `BLOCKED`。當將已通過的主張設定為 40% 結算能力時，結果成為 `PARTIAL`：13.2264 kWh 可覆蓋、19.8396 kWh 為缺口。

因此，評審可以在同一個展示中直接看到：**同一份證據、不同政策、不同金融後果，而且每一步都可檢查。**

## 三、系統功能簡介

### 1. 證據與保證分類

系統接收案例與證據物件，保留來源、量測區間、摘要、診斷、雜湊識別與保證層級。證據內容與分析情境分開，避免模型假設被誤認成實際觀測。

### 2. 版本化政策准入

每個政策均具有獨立識別與版本。准入階段逐條執行規則；若任何必要條件失敗，系統立即產生 `BLOCKED` 並記錄阻擋規則，不繼續虛構後續數量。

### 3. 數量上限與限制歸因

通過准入後，系統計算多個可比較上限，例如證據支持容量、來源／政策容量與資源情境容量，再採用最低有效值作為可支持的最大主張。結果同時記錄哪一個 ceiling 真正成為 binding constraint。

### 4. 結算壓力測試

使用者可在不改變原始證據與決策身份的前提下，調整宣告的結算能力，觀察 `SETTLED`、`PARTIAL` 或 `SHORTFALL`。此功能使「可提出多少」與「實際能覆蓋多少」保持分離。

### 5. 決策收據、Lineage 與重現

每次結果保留案例、證據、政策、規則、決策與執行版本的識別。系統可產生 Decision Receipt、Research Capsule 與可攜式 Claim Assessment Package，並透過自動化測試驗證重建結果與輸出一致性。

### 6. 公開工作台與比較

網頁工作台提供控制案例、政策、保證情境與結算條件的介面。使用者可比較受控案例、查看外部資料 checkpoint、開啟完整分析、追查決策 lineage，並檢查公開研究檔案的雜湊一致性。

## 四、系統特色

### 可稽核而非只可執行

一般規則引擎回答「結果是什麼」；Policy Lab 同時回答「為什麼」、「依哪一版政策」、「哪條規則阻擋」、「哪個上限限制」、「哪些事實仍未證明」。

### 對失敗結果友善

`BLOCKED`、數量被限制、結算不足或證據保證不足都被視為有效分析結果。系統不以提高通過率為目標，而以防止過度主張為目標。

### 確定性與可重現性

相同案例、證據、情境、政策與計算器版本會產生相同決策身份。CI 會重新建構外部案例、驗證 schema、重現決策並比較可攜式評估包，降低展示與實際邏輯分離的風險。

### 可擴充的物件與政策架構

目前雖以能源案例展示，但核心由明確 schema、PolicyManifest、EvidenceEnvelope、DecisionResult、SettlementResult 等物件構成，新領域可以透過定義證據、政策與可比較上限來擴充，而不是複製整套應用程式。

### 保留限制，不用介面包裝證據

外部 Ausgrid 案例仍維持 L0；公開來源、漂亮 UI、雜湊、收據或歷史區塊鏈元件都不會自動把來源提升為已驗證的實體量測。這種「不自動升級」本身就是系統安全與治理設計的一部分。

## 五、系統開發工具與技術

- **前端：** React、Vite、JavaScript，提供 Overview、Investigation、Research、Field Use、Programme、Analysis Lab 與 Verification Hub 等介面。
- **決策核心：** Node.js／JavaScript 的 deterministic constraint core，使用結構化案例、證據、政策、規則與結算物件。
- **資料與 Schema：** JSON／JSON Schema，保存 CaseManifest、EvidenceEnvelope、PolicyManifest、DecisionResult、Receipt、Assessment 等機器可讀物件。
- **測試與重現：** Node test、前端測試、Playwright 瀏覽器測試、自動化外部案例工作流程、byte-identical rebuild 驗證。
- **CI/CD：** GitHub Actions，自動執行 current-surface integrity、測試、conformance、秘密掃描、安全檢查、公開頁面建置與 live smoke test。
- **部署：** GitHub Pages 公開研究工作台；核心計算不需伺服器帳號或錢包即可操作。
- **歷史參考：** Repository 保留早期 SolarPunk／SPK／Sepolia 實作作為研究沿革與參考，但不作為目前 Policy Lab 的主要產品身份。

## 六、系統使用對象

Policy Lab 目前首先定位為研究、驗證與決策設計工具，適合：

1. 研究外部證據與金融授權關係的研究者與學生；
2. 設計 tokenized real-world asset、抵押／儲備主張或能源／環境憑證流程的技術與產品團隊；
3. 需要檢查「哪一份證據、哪一版政策、哪一個上限」造成結果的風險、治理或稽核角色；
4. 希望比較不同政策如何改變相同證據後果的機構或政策研究者。

以上為系統的應用對象與可擴充方向，不代表目前已存在商業客戶或正式機構試點。現階段下一個實證門檻仍是取得一個可歸屬的 owner/operator 證據來源，進一步測試來源保管、驗證與政策要求。

## 七、系統使用環境

公開版本可直接透過現代桌面或行動瀏覽器開啟，不要求註冊帳號。主要工作台部署於 GitHub Pages。使用者可切換 Overview 與 Full Analysis，在受控案例中改變政策與保證情境、執行結算壓力、查看 receipts／lineage，並瀏覽公開外部資料 checkpoint。

開發與重現環境使用 Node.js 22、npm、React/Vite 與 GitHub Actions。核心測試、前端 build 與瀏覽器驗證可在標準 Linux CI 環境執行。歷史 Solidity／Sepolia 元件屬參考路徑，並非目前 Policy Lab 基本操作所必需。

## 八、結語

Policy Lab 處理的不是「如何讓金融主張更容易成立」，而是相反的問題：**當一個金融決策宣稱有外部證據支持時，系統能否清楚說明這份證據真正允許它主張多少，以及在哪裡必須停止？**

目前公開實作已能以受控案例與一個外部 Ausgrid 資料 checkpoint 展示：同一份證據在不同政策下可以產生有限准入或直接阻擋；即使准入，數量仍受明確上限約束；即使數量成立，結算仍可能出現缺口；所有結果可透過決策身份、收據、lineage 與可攜式評估包重現。

本作品的延展價值在於把「外部資料如何轉換為金融權限」從隱藏假設變成可見、可執行、可挑戰的系統流程。下一階段並不是加入更多華麗功能，而是讓現有架構接觸更高品質、可歸屬的外部來源，驗證哪些規則在真實情境下仍然成立、哪些必須修改。
